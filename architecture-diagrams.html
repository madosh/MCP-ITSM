Key Architecture Features

  • 3-Tier Architecture: Frontend (React), Backend (Express), Database (MongoDB)
  • MCP Integration: Model Context Protocol server for LLM interactions
  • Security Layers: JWT authentication, role-based authorization, input validation
  • Multi-ITSM Support: ServiceNow, Jira, Zendesk connectors
  • Error Handling: Global error boundary, structured logging

Authentication & Authorization Flow

Complete user authentication and protected resource access flow

sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant Auth["Auth Middleware"]
    participant DB["MongoDB"]

    User->>Frontend: Navigate to /dashboard
    Frontend->>Frontend: Check localStorage token

    alt No token
        Frontend->>User: Redirect to /login
        User->>Frontend: Enter credentials
        Frontend->>API: POST /api/auth/login
        API->>Auth: validate credentials
        Auth->>DB: Query user
        DB-->>Auth: User data
        Auth->>Auth: Compare password
        Auth->>Auth: Generate JWT
        Auth-->>API: Token + User
        API-->>Frontend: 200 OK
        Frontend->>Frontend: Save token
        Frontend->>User: Redirect to /dashboard
    else Has token
        Frontend->>API: GET /api/integration
        API->>Auth: Verify JWT
        Auth->>DB: Get user
        DB-->>Auth: User object
        Auth->>Auth: Check role
        alt Authorized
            Auth->>API: Allow request
            API-->>Frontend: 200 OK + data
            Frontend->>User: Display page
        else Unauthorized
            Auth-->>Frontend: 403 Forbidden
            Frontend->>User: Access denied
        end
    end

Authentication Features

  • JWT Tokens: Secure token-based authentication
  • Password Hashing: bcryptjs for secure storage
  • Role-Based Access: Admin, User, Integrator roles
  • Protected Routes: Frontend guards prevent unauthorized access

Resource Access Control

Authorization decision tree

flowchart TD
    Start([Request]) --> Auth{Authenticated?}
    Auth -->|No| Reject401[401 Unauthorized]
    Auth -->|Yes| Admin{Is Admin?}
    Admin -->|Yes| Allow[✓ Allow Access]
    Admin -->|No| Owner{Is Owner?}
    Owner -->|Yes| Allow
    Owner -->|No| Manager{Is Manager?}
    Manager -->|Yes| Allow
    Manager -->|No| Public{Is Public?}
    Public -->|Yes| Allow
    Public -->|No| Reject403[403 Forbidden]

    Allow --> Process[Process Request]
    Process --> Success[Return Data]

API Request Lifecycle

Complete middleware pipeline

sequenceDiagram
    participant Client
    participant Express
    participant MW["Middleware"]
    participant Route
    participant DB

    Client->>Express: HTTP Request
    Express->>MW: CORS
    MW->>MW: Helmet
    MW->>MW: Rate Limit

    alt Rate Limited
        MW-->>Client: 429 Too Many
    else OK
        MW->>MW: Authenticate
        alt Invalid Token
            MW-->>Client: 401 Unauthorized
        else Valid
            MW->>MW: Authorize
            alt Forbidden
                MW-->>Client: 403 Forbidden
            else Allowed
                MW->>MW: Validate
                alt Invalid
                    MW-->>Client: 400 Bad Request
                else Valid
                    MW->>Route: Process
                    Route->>DB: Query
                    DB-->>Route: Data
                    Route-->>Client: 200 OK
                end
            end
        end
    end

Middleware Stack

  • CORS: Cross-origin handling
  • Helmet: Security headers
  • Rate Limiting: DDoS protection
  • Authentication: JWT verification
  • Authorization: Role checking
  • Validation: Joi schemas
