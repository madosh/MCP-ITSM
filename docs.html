📋 Overview

MCP ITSM exposes a standardised set of MCP capabilities so LLM clients need only learn one interface instead of five ITSM APIs. Every tool carries safety annotations (readOnlyHint, destructiveHint) so models know what they can call autonomously.

New in v3.0.0 (May 2026) Upgraded to MCP spec 2025-11-25 and SDK 1.28.0. Added tool annotations, Zod validation, MCP Resources (KB + tickets), MCP Prompts (templates), SDK Client transport (replaces raw child-process bridge), metrics store, and the live monitoring dashboard.

🏗 System Architecture

Three distinct layers: MCP clients talk to the MCP server over stdio, while the Express backend bridges browser clients via the official MCP SDK Client, and the React frontend drives both the ticket manager and the monitoring dashboard.

🔧 MCP Tools

All 7 tools are registered via McpServer.tool() with Zod input schemas and safety annotations. LLM clients read annotations to decide whether a tool is safe to call without user confirmation.

Tool name Title Read-only Idempotent Required params
create_ticketCreate Ticket——title, description
get_ticketGet Ticketyesyesticket_id
update_ticketUpdate Ticket——ticket_id
list_ticketsList Ticketsyesyes—
assign_ticketAssign Ticket—yesticket_id, user_id
add_commentAdd Comment——ticket_id, comment
search_knowledge_baseSearch KByesyesquery

All tools share an optional system parameter: servicenow · jira · zendesk · ivanti_neurons · cherwell (default: jira)

💬 MCP Prompts New in v3

Prompts are guided message templates that client UIs can surface to users before starting a tool-call sequence. They accept typed Zod arguments and return pre-composed messages.

NameDescriptionRequired argsOptional args
create-incident-ticket P1/P2 incident ticket with structured description template title system, affected_service
ticket-status-report Structured summary of the current ticket queue by priority — filter_status
kb-search-assist Search KB before creating a ticket — self-service first issue_description —

📊 Monitoring Dashboard New in v3

The React frontend includes a live monitoring dashboard at /mcp-monitor that polls the backend every 10 seconds. Metrics are tracked in the Express layer — no external monitoring service required.

What it shows

  • Server connected / disconnected with uptime
  • Total calls, success rate, failed count
  • Per-tool call counts + average latency
  • Tool list with annotation badges
  • Registered resources and prompts
  • Live activity log — last 20 calls

🚀 Quick Start

Install dependencies — 3 packages

Root (MCP server + Zod), backend (Express + SDK Client), frontend (React)

Configure environment variables

Copy .env.example files; set MONGODB_URI and JWT_SECRET in backend/.env

Start 3 services (3 terminals)

MCP server on stdio · Express API on :5000 · React dev server on :3000

📡 API Reference

All /api/mcp/* routes require Authorization: Bearer <token> from the /api/auth/login response.

MethodPathDescriptionAuth
GET/healthBackend health — no MCP needed—
GET/api/mcp/healthMCP server connectivity + uptimeJWT
GET/api/mcp/metricsTool-call counts, latency, recent activityJWT
GET/api/mcp/tools/listAll registered tools with Zod schemas + annotationsJWT
POST/api/mcp/tools/callCall a tool — body: { name, arguments }JWT
GET/api/mcp/resources/listAll registered MCP resourcesJWT
GET/api/mcp/prompts/listAll registered MCP promptsJWT

curl example

# 1. Login and capture token
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"password"}' \
  | jq -r '.token')

# 2. Search the knowledge base
curl -X POST http://localhost:5000/api/mcp/tools/call \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "search_knowledge_base",
    "arguments": { "query": "vpn", "limit": 3 }
  }'

# 3. Check live metrics
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:5000/api/mcp/metrics

📈 What Changed — v1 → v3

The project was originally built on MCP spec 2024-11-05 with SDK 1.0.4. Here's what was upgraded in May 2026 to reach spec 2025-11-25 and SDK 1.28.0.
